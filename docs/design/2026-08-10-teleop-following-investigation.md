# 视觉遥操"不跟手"根因调研报告

> 调研日期: 2026-08-10
> 范围: W1 手势映射视觉遥操全链路（相机 → MediaPipe 21kp → 3D 源 → JointMapper → 校准 → 1€滤波 → 增益/方向 → 电机限位 → Dynamixel）
> 方法: 代码级逐段核对 + 确定性滤波仿真（/tmp/leap_lag_sim.py）+ 离线图像探针（/tmp/leap_offline_probe.py）+ 合成攥拳探针（/tmp/leap_clench_probe.py）
> 结论性质: 全部基于源码/数据/仿真，可复现；真机复核项单列（§5）

---

## 0. 结论摘要（TL;DR）

"不跟手"不是单一根因，而是**多因叠加**，按证据强度排序：

| 序 | 根因 | 证据类型 | 贡献的症状 |
|----|------|---------|-----------|
| 1 | **滤波级联滞后**：angle_filter 0.5Hz + kp_smoother 1.0Hz 级联 | 确定性仿真 | 跟随滞后（慢半拍） |
| 2 | **滤波动态幅度衰减**：1Hz 手势输出幅度仅剩 30% | 确定性仿真 | 跟不足（动态） |
| 3 | **高增益→高噪声→重滤波 恶性循环**：DIP 增益 2.8-3.0 放大伪3D 折叠噪声 → 被迫 0.5Hz 压噪 | 代码+数值 | 滞后 + 抖动此消彼长 |
| 4 | **拇指驱动不足**：mcp 增益 0.60 + 基线 0.31 + PIP motor 限位 0.81 rad | 数值+离线数据 | 拇指对掌不足 |
| 5 | **伪3D 与 world-3D 几何发散**：固定增益无法补偿变量压扁 | 离线图像数据 | 振幅/形状不可靠 |
| 6 | **三源共用增益/基线**（配置耦合） | 代码 | M 键切源时角度突变 |

**一句话**：系统为了压制"折叠姿势 landmark 抖动"，把滤波调到 0.5Hz（牺牲跟手响应），同时把 DIP 增益调到 3.0（放大噪声），这是**稳定性-响应性失衡**的累积结果。"不跟手" = 滤波滞后 + 滤波幅度衰减 + 拇指结构性欠驱 + 源间不一致。

## 1. 症状谱系逐一判定

### 1.1 跟随滞后（慢半拍）—— ✅ 确认存在，结构性，主因

**证据链**（确定性仿真，30fps，复刻 demo_hamer3d 伪3D 路径 `kp_smoother(63,1.0Hz)→angle_filter(16,0.5Hz)`）：

| 输入 | 当前(0.5Hz) | 1.0Hz(先前) | 2.0Hz |
|------|------------|------------|-------|
| 阶跃 63% | 500ms | 333ms | 267ms |
| 阶跃 90% | 967ms | 633ms | 500ms |
| 快速斜坡 0→1.5rad/0.33s 滞后 | **400ms** | 300ms | 233ms |
| 1Hz 正弦相滞后 | 267ms(8帧) | 200ms | 167ms |

- 代码定位：`demo_hamer3d.py:212` `angle_filter = OneEuroFilter(n_joints=16, min_cutoff=0.5, beta=0.005)`；`:301` `pseudo_smoother = OneEuroFilter(63, min_cutoff=1.0, beta=0.004)`。
- **0.5Hz 是从 1.0Hz 降下来的**（demo 注释：为压"折叠姿势高频颤动"）。代价就是 300-500ms 跟手滞后——人手一个快速攥拳（0.33s）机器手要慢 0.4s 才到位，肉眼明显"慢半拍"。

### 1.2 振幅不足/跟不足 —— ✅ 确认存在，两个独立来源

**来源 A：滤波本身衰减动态幅度（新发现，非几何问题）**

| 输入 | 当前(0.5Hz)输出幅值 | 1.0Hz | 2.0Hz |
|------|--------------------|-------|-------|
| 1Hz 正弦(幅1.0) | **0.30** | 0.46 | 0.58 |

- 1Hz = 每秒一个完整的张-握周期（已经很慢）。当前配置下机器手动态幅度只剩 30%。**即使几何/增益完全正确，动起来也"跟不足"**。这是滞后之外、被低估的幅度杀手。
- 注意：这不影响静态握拳幅度（静态会收敛到全值），但遥操时手几乎总在动。

**来源 B：伪3D 几何压扁（已部分补偿但不可靠）**

离线图像探针（`/tmp/leap_offline_probe.py`，复刻完整 demo 路径，raw = gain=1 时角度）：

| 图 | 关节 | 伪3D raw | world-3D raw | 发散方向 |
|----|------|---------|-------------|---------|
| test1 | ID3 食指DIP | +0.011 | +0.445 | 伪3D 低估 |
| test3 | ID7 中指DIP | +0.118 | +0.534 | 伪3D 低估 |
| test5 | ID12 拇指MCP | +0.825 | +0.193 | 伪3D 高估 |
| test5 | ID11 小指DIP | +0.256 | +0.880 | 伪3D 低估 |
| test1 | ID6 中指PIP | +1.883 | +1.013 | 伪3D 高估 |

- 伪3D 的 z 方向在折叠时既可能低估也可能高估，**方向/幅度随姿态变**。固定增益（即使 3.0）无法同时修正各姿态 → 某些姿态屈曲不足，某些又过冲。
- 合成攥拳探针（`/tmp/leap_clench_probe.py`）：对理想攥拳做 z×0.6/×0.3 压缩后，当前增益（mcp/pip/dip 0.8-2.9）**基本能补回**屈曲（CAL 仍 2.0-2.6），说明"理想几何下增益够用"；但**真实 MediaPipe 伪3D 的折叠行为比均匀 z 压缩更糟**（指尖 landmark 相互吸附/塌陷），test5 拇指 raw 0.83 → CAL≈0 就是实证。

### 1.3 抖动/跳变 —— ✅ 已被大量工作压制（勿重复），但代价是 1.1/1.2

- git 已做：手丢失平滑回 OPEN（`549eefa`）、帧质量门控 `_MIN_VIS`（`0c773a0`）、掌参考系时域平滑（`5faea94`）、bbox EMA、world 源（`af40bd0`）、限位裁剪（`cb4879d`）。
- **抖动仍在的原因**：DIP 增益 2.88-3.0 把伪3D 折叠噪声放大 3 倍 → 不重滤波就抖 → 重滤波就滞后。这是 §3 的恶性循环。
- 建议方向：**从源头降噪**（折叠 landmark 修复 / 每关节自适应滤波 / 换源），而不是继续加重滤波。

### 1.4 方向错 —— ❌ 已解决（勿重查）

- `JOINT_DIR`（`demo_hamer3d.py:239`）已真机实测修正（thumb mcp ID12=+1 例外）。不是当前问题。

### 1.5 手指独立性差 —— ⚠️ 结构性风险，未离线确诊

- 扇角以**中指近端方向 mid_dir** 为 0° 基准（`joint_mapper.py:_palm_frame`）。中指弯曲/转动会改变其他指扇角基准 → 弯中指带动食指/小指 side 角。
- 掌参考系时域平滑（frame_smoother 1.0Hz）已缓解但不消除（它平滑的是参考系本身的跳变，不是"参考系随中指姿态改变"这一耦合）。
- 离线 test3 ID8（小指 side）raw=1.07 而小指笔直——疑似参考系变化导致的 side 噪声（被 gain 0.10 掩盖，但说明 fan 计算本身有扰动）。

### 1.6 拇指对掌不足 —— ✅ 确认存在，结构性

数值证据（`joint_gain_3d.json` + `calibration_3d.json` + `motor_limits.json` + `poses.json`）：

| 项 | 值 | 问题 |
|----|-----|------|
| ID12 拇指MCP 增益 | 0.60（默认 _JOINT_GAIN 是 1.5） | 反向调小 |
| ID12 校准基线 | 0.306 rad | 基线偏高 |
| 离线 test5 拇指 raw | 0.825 → CAL ≈ 0.19（平滑后 -0.07） | **拇指 mcp 输出≈0** |
| _OPP 补偿有效增量 | 0.6 权重 × 0.6 增益 = **0.36 rad** | 量级不足（人手对掌 mcp 需 1.0-1.3） |
| ID14 拇指PIP motor 可用屈曲 | **0.81 rad**（OPEN=2.157, min=1.351） | 机械上被限位压住 |
| ID13 拇指side 增益 | 3.0（基线 1.451） | 3 倍放大噪声；方向符号需真机核 |

- 结论：拇指 mcp/pip 驱动不足 + 对掌补偿量级不足 + PIP 机械行程小 → **攥拳时拇指横跨掌心不到位**（对掌不足）。

### 1.7 过冲/回弹 —— ⚠️ 需真机验证

- DIP 增益 2.8-3.0 + 电机限位裁剪 + PID（kP=600, kD=200）可能产生"到位后晃两下"。离线无法验证，列入 §5 真机复核。

## 3. 架构性根因（横向总结）

### 3.1 稳定性-响应性恶性循环（本次最重要发现）

```
伪3D 折叠时 landmark 抖动
  → DIP 增益 3.0 放大抖动（为补偿压扁而调高增益）
  → 抖动明显 → 把 angle_filter 从 1.0Hz 降到 0.5Hz 压噪
  → 滞后 300-500ms + 动态幅度衰减 70%
  → "不跟手"
```

**修复的正确位置在"源"（折叠 landmark 噪声），不在"输出端重滤波"。** 任何只调滤波的方案都会在"抖"和"慢"之间二选一。

### 3.2 三源配置耦合

- 三种 3D 源几何特性不同（伪3D z 压缩、world-3D 米制稳定、hamer 真3D 慢），却共用一套 `joint_gain_3d.json` 增益和 `calibration_3d.json` 基线。
- 增益是为伪3D 压扁调的（DIP 3.0），切到 world-3D 会过度放大；基线是某次 SPACE 在某个源下记录的，切源后基线不匹配。
- M 键切源时角度跳变 = 上述耦合的直接后果。

### 3.3 拇指管线未针对 LEAP 机械行程校准

- 增益/基线/限位三者叠加把拇指 mcp/pip 输出压到 ≈0-0.4 rad（人手对掌需 1.0-1.3）。
- 拇指 PIP motor 实测行程 0.81 rad 是本机的物理约束，需重新确认测量或接受受限。

## 5. 待真机复核项

1. **攥拳 HUD 实测**（half-clench 文档 Step 2）：攥拳时 `print_angles_table` 的 mcp/pip/dip 是否 ≥1.5 rad——直接区分"角度没算够"还是"增益/限位"。**这是判据，离线无法替代。**
2. **拇指 side（ID13）符号方向**：motor 限位 min/max 哪端对应"跨掌心"（对掌）——决定对掌方向是否被限位压死。真机上逐指弯拇指观察。
3. **过冲/回弹**：快速张握 10 次，观察 DIP 是否到位后回弹。
4. **拇指 PIP（ID14）限位重测**：确认 0.81 rad 是否为真实机械行程，还是测量时全开位没推到物理伸直端。
5. **实际帧率**：真机 loop 实际 fps（HUD 有显示）。若 <30fps（尤其 hamer 源），滞后预算要再加 MediaPipe 推理 + Dynamixel 写入时间。
